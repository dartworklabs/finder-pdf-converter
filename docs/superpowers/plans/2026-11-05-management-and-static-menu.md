## Frozen design and boundaries

The existing `installer/` capability owns management and its own preferences; UI → its existing pure model and UI → public backend commands are the only backend dependencies. `inspect` refreshes on each window open, mutations require explicit clicks, and errors cannot turn into healthy status. Keep `installer/managed-install.sh`, `installer/managed-engine.js`, `installer/stage-managed.sh`, all 37 payload files, conversion/print sources and format/print preferences byte-identical. This avoids an unnecessary backend full rerun only when their frozen hashes, tests and public contract actually remain unchanged. No new user runtime, network, updater, polling service, automatic permission or public release.

Name the retained package `Finder PDF Converter.app` in `~/Applications`; the manager uses only its own signed bundle payload for `inspect/install/recover`, so replacing an owned manager with a later locally built package supplies the later source; it never updates itself or downloads anything. Default delivery: build an ad-hoc local developer artifact and give the user clear Finder copy/open instructions. An existing destination, symlink, foreign object or ambiguous ownership must never be overwritten by a script; stop and preserve it. User-directed manual replacement of an existing manager is outside automatic backend installation and requires current evidence and a separately explicit user decision. Source update remains the existing explicit Install/Update action, not a manager update.

Menu visibility and login launch are separate booleans, both default false. Manual launch opens manager. With menu enabled, close window keeps a single static `NSStatusItem`; its menu opens manager (refresh inspection) or Quit. Disable menu removes the item but does not quit an active task; if no window remains, exit after guarded work completes. Login launch, if enabled, uses a bundled short-lived launch-agent helper via `SMAppService`, which requests the manager with an explicit background argument and exits; the manager creates the menu only if menu preference is enabled, otherwise exits cleanly. Never register the manager itself as the agent: unregister may kill the agent process. Registration may immediately launch the helper, so enabling login must not duplicate an already running manager or mutation. Login enabled/menu disabled is a valid independent configuration. Quit leaves stored settings unchanged; next login follows settings. `SMAppService` current status is authoritative, including approval-required, unavailable and errors; a requested toggle is not success until actual status confirms it. Preferences are scoped to the app, strictly parsed; malformed values fail closed to off without clobbering other preferences. A native OS denial must be shown truthfully with user-controlled recovery. Do not set login items silently or override system security.

The status item uses a fixed document symbol/image with native template rendering. The same image remains fixed in idle, inspect, mutation, success and failure: no animation, rotation, pulsing, blinking, or replacement. Text/window carries progress. No nested event loop, conversion ownership handoff, process group signal, unrelated cleanup or modification of TCC/printer settings. All Close/Command-Q/menu Quit paths preserve existing inspect cleanup and mutation guard; Finder actions run without manager or menu. Reopening a closed window resets `finished` correctly, and concurrent invocations cannot duplicate mutations or orphan the owned task.
